Dev Trade-offs
What each direction actually costs to build.
Option A · Monoline
Pros
• Ship now — bundle 30 SVGs with the app
• Consistent rendering everywhere
• Theme adapts (stroke colour reacts to mode)
• Fits the editorial Tokyo Riso voice perfectly

Cons
• Can't distinguish Sushi Tei from Koufu (both Food)
• Less "personal" without merchant recognition

Effort · 2–3 days
Option B · Merchant Logo
Pros
• Instantly recognisable — feels premium
• Matches mental model (Mint, Copilot, Monzo)
• Category dot still signals tagging

Cons
• Brandfetch API ($30+/mo) or scrape clearbit
• Need merchant-name normalisation pipeline
• Local cache + fallback chain logic
• Some SG merchants won't have logos

Effort · 1–2 weeks · ongoing cost
Option C · Initials
Pros
• Zero assets, zero API calls
• Pure brutalist typography vibe
• Works for any merchant instantly
• Fastest visual parsing

Cons
• Two "S" merchants look the same
• Less personality, more clinical
• Brand recognition lost

Effort · 1 day
My take
Ship Option A (Monoline) as v1. It's cheap, looks like the rest of the design language, and lets you focus on the actual problems (CSV import, CPF, AI). Then introduce Option B (Merchant logos) as a v2 enhancement — Brandfetch the top 200 SG merchants and progressive-enhance the line icons with logos as they get cached. Best of both: line icons as fallback, logos when available. Option C is too quirky for the long haul.
